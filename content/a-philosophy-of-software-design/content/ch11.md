# 第11章 设计两次 {#chapter-11}

<!-- SOURCE pdf-099-b002 -->
<div id="pdf-099-b002" hidden></div>
软件设计很难，关于模块或系统结构的第一个想法，不大可能就是最佳设计。每个重要设计决定都考虑多个方案，结果会好得多：设计两次。

<!-- SOURCE pdf-099-b003 -->
<div id="pdf-099-b003" hidden></div>
假设正在为图形界面文本编辑器设计管理文件文本的类。第一步是确定这个类向编辑器其他部分提供的接口。先考虑几种可能性，别急着采用脑中冒出的第一个想法。可以用面向行的接口，提供插入、修改、删除整行文本的操作；也可以用面向单个字符插入、删除的接口；第三种是面向字符串的接口，操作任意范围的字符，允许跨越行边界。这时无须确定每种方案的所有功能，勾勒几个最重要的方法就够了。

<!-- SOURCE pdf-099-b004 -->
<div id="pdf-099-b004" hidden></div>
尽量选择差异很大的方案，这样能学到更多。即使确信只有一种合理方案，也考虑第二种设计，不管觉得它有多糟。思考它的弱点，再与其他设计的特点比较，会有所收获。

<!-- SOURCE pdf-099-b005 -->
<div id="pdf-099-b005" hidden></div>
各方案大致成形后，列出各自的优缺点。接口最需要考虑的是上层软件使用起来是否方便。上面的例子中，面向行和面向字符的接口，都要求使用文本类的软件多做工作。面向行的接口要求上层在剪切、粘贴选区等涉及部分行或多行的操作中，自行拆分、合并行。面向字符的接口则要求通过循环实现修改多个字符的操作。还应考虑其他因素：

<!-- SOURCE pdf-100-b000 -->
<div id="pdf-100-b000" hidden></div>
- 某个方案的接口是否比另一个简单？文本例子中，各种接口都相对简单。
- 某个接口是否更通用？
- 某个接口是否允许更高效的实现？文本例子中，面向字符的方式很可能明显更慢，因为每个字符都要单独调用文本模块。

比较过不同设计后，更容易判断最佳方案。它可能是已有方案之一，也可能融合几个方案的特点，产生比所有原方案都好的新设计。

<!-- SOURCE pdf-100-b001 -->
<div id="pdf-100-b001" hidden></div>
有时所有方案都不太吸引人，这时看看能否提出更多方案。利用原方案暴露的问题来推动新设计。如果设计文本类时只考虑了面向行和面向字符的方式，可能会发现两者都别扭，因为都要求上层完成额外的文本操作。这是危险信号：既然有文本类，它就应该负责所有文本操作。要消除上层这些额外操作，文本接口需要更贴近上层软件实际执行的操作；它们未必对应单个字符或单行。沿着这个思路，应该会得到面向范围的文本 API，消除前两个设计的问题。

<!-- SOURCE pdf-100-b002 -->
<div id="pdf-100-b002" hidden></div>
“设计两次”可以用于系统的多个层级。对模块，可以先用它选择接口，如上所述；设计实现时，再用一次。文本类可以考虑行链表、固定大小的字符块，或“间隙缓冲区”（gap buffer）等实现。实现与接口的目标有所不同：实现最需要考虑简单性和性能。系统更高层也适合探索多个方案，例如选择用户界面功能，或将系统分为主要模块。无论哪种情况，有几个备选方案可比较，总更容易找到最佳做法。

<!-- SOURCE pdf-101-b000 -->
<div id="pdf-101-b000" hidden></div>
设计两次无须额外花很多时间。对于类这样的小模块，考虑备选方案可能只需一两个小时；相比实现这个类所需的几天或几周，这点时间很少。初期的设计尝试很可能带来明显更好的设计，收益足以抵偿设计两次的时间。大模块的初步设计探索会耗时更久，但实现也更久，改进设计的收益也更大。

<!-- SOURCE pdf-101-b001 -->
<div id="pdf-101-b001" hidden></div>
我发现，一些很聪明的人有时难以接受“设计两次”。成长过程中，他们发现面对任何问题，迅速想到的第一个点子就足以取得好成绩，无须考虑第二、第三种可能。这容易养成不好的工作习惯。但随着成长、晋升，他们会进入问题越来越难的环境。每个人最终都会到达这样的阶段：第一个想法已不够好。无论多聪明，想取得出色成果，都得考虑第二种，甚至第三种可能。大型软件系统设计就属于这类问题，没有谁能保证第一次就做对。

<!-- SOURCE pdf-101-b002 -->
<div id="pdf-101-b002" hidden></div>
遗憾的是，我常看到聪明人坚持实现脑中冒出的第一个想法，发挥不出实际潜力，也让同事合作起来很烦恼。也许他们潜意识里相信“聪明人第一次就能做对”，尝试多个设计就表示自己不够聪明。事实并非如此：他们的智力没有问题，问题本身确实很难！而且，这是好事：解决必须认真思考的难题，比处理完全无须思考的简单问题更有乐趣。

<!-- SOURCE pdf-101-b003 -->
<div id="pdf-101-b003" hidden></div>
设计两次不仅改进设计，也提升设计能力。构思、比较多种方案的过程，会帮助理解哪些因素让设计更好或更差。久而久之，就更容易排除糟糕的设计，找到出色的方案。
