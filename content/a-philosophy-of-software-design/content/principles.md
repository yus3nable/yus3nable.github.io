# 设计原则汇总 {#principles}

<!-- SOURCE pdf-185-b001 -->
<div id="pdf-185-b001" hidden></div>
以下是本书讨论的主要软件设计原则：

<!-- SOURCE pdf-185-b002 -->
<div id="pdf-185-b002" hidden></div>
1. 复杂性是逐步积累的，细微之处也要认真对待（见原书第 11 页）。

<!-- SOURCE pdf-185-b003 -->
<div id="pdf-185-b003" hidden></div>
2. 代码能运行还不够（见原书第 14 页）。

<!-- SOURCE pdf-185-b004 -->
<div id="pdf-185-b004" hidden></div>
3. 持续投入少量精力，改善系统设计（见原书第 15 页）。

<!-- SOURCE pdf-185-b005 -->
<div id="pdf-185-b005" hidden></div>
4. 模块应该具有深度（见原书第 22 页）。

<!-- SOURCE pdf-185-b006 -->
<div id="pdf-185-b006" hidden></div>
<!-- SOURCE pdf-185-b007 -->
<div id="pdf-185-b007" hidden></div>
5. 接口设计应让最常见的用法尽可能简单（见原书第 27 页）。

<!-- SOURCE pdf-185-b008 -->
<div id="pdf-185-b008" hidden></div>
<!-- SOURCE pdf-185-b009 -->
<div id="pdf-185-b009" hidden></div>
6. 对模块来说，接口简单比实现简单更重要（见原书第 55、71 页）。

<!-- SOURCE pdf-185-b010 -->
<div id="pdf-185-b010" hidden></div>
7. 通用模块往往更深（见原书第 39 页）。

<!-- SOURCE pdf-185-b011 -->
<div id="pdf-185-b011" hidden></div>
8. 将通用代码与专用代码分开（见原书第 62 页）。

<!-- SOURCE pdf-185-b012 -->
<div id="pdf-185-b012" hidden></div>
9. 不同层次应采用不同的抽象（见原书第 45 页）。

<!-- SOURCE pdf-185-b013 -->
<div id="pdf-185-b013" hidden></div>
10. 将复杂性下沉（见原书第 55 页）。

<!-- SOURCE pdf-185-b014 -->
<div id="pdf-185-b014" hidden></div>
11. 通过设计消除错误和特殊情况（见原书第 79 页）。

<!-- SOURCE pdf-185-b015 -->
<div id="pdf-185-b015" hidden></div>
12. 设计两次（见原书第 91 页）。

<!-- SOURCE pdf-185-b016 -->
<div id="pdf-185-b016" hidden></div>
<!-- SOURCE pdf-185-b017 -->
<div id="pdf-185-b017" hidden></div>
13. 注释应说明从代码中看不出来的信息（见原书第 101 页）。

<!-- SOURCE pdf-185-b018 -->
<div id="pdf-185-b018" hidden></div>
<!-- SOURCE pdf-185-b019 -->
<div id="pdf-185-b019" hidden></div>
14. 软件设计应以方便阅读为目标，不能只图编写方便（见原书第 149 页）。

<!-- SOURCE pdf-185-b020 -->
<div id="pdf-185-b020" hidden></div>
<!-- SOURCE pdf-185-b021 -->
<div id="pdf-185-b021" hidden></div>
15. 软件开发的每次增量应围绕抽象来划分，不宜以功能来划分（见原书第 154 页）。
